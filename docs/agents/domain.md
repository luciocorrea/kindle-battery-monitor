# Domain docs

This repository uses one root CONTEXT.md and docs/adr/.

Before domain exploration, read CONTEXT.md and the ADRs relevant
to the work. Use glossary terms in tickets, designs, and tests.
Surface conflicts with an existing ADR explicitly.

Follow AGENTS.md for additional protocol, compatibility, startup,
and build contracts relevant to the task.

If a glossary or ADR document is absent, continue with the
available evidence. Create domain documentation when a term or
decision is actually resolved.
